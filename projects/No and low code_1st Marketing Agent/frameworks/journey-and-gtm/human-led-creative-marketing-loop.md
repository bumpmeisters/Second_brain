# Human-Led Creative Marketing Loop

## Framework Job

Preserve the historical framework identity and route new work to its two canonical replacements.

## Classification And Fidelity

Deprecated composite project framework.

Project adaptation: the former combined strategy-and-execution loop was split on 2026-07-26 because Strategic Creative Direction and Content Execution have different decision jobs, objects, owners, and gates.

## Use When

- Reading historical project records that cite this framework.
- Resolving an old link before routing work to a replacement.

## Do Not Use When

- Creating a new creative direction, content brief, or content asset.
- Selecting an active canonical framework for a new run.

## Minimum Required Inputs

- The historical reference or request.
- The current stage: strategic direction or content execution.

## Core Model

Route:

- What should be said -> `projects/content-operating-system/frameworks/creative-direction/strategic-creative-direction.md`.
- How an approved direction should be expressed -> `projects/content-operating-system/frameworks/execution/content-execution.md`.
- Campaign role before creative direction -> `campaign-role-architecture.md` in this folder.

## Question Engine

### Minimum Viable Questions

- Is the campaign role already clear?
- Is the task deciding what should be said?
- Is the task deciding how an approved direction should be expressed?
- Does an approved Creative Direction exist?
- Would the request change thesis, audience, proof, or angle?
- Is the user asking for execution or publication?
- Which canonical replacement owns the next decision?
- Which historical record must retain this deprecated name?

### Deepening Questions

- Does the old artifact combine strategy and execution?
- Which fields belong in the Creative Direction?
- Which fields belong in the execution brief?

### Counter-Questions

- Would keeping the combined loop recreate duplicated ownership?
- Is a downstream execution request hiding a missing upstream decision?

### Optional Modules

- Historical migration mapping.
- Link compatibility review.

## Branching And Stop Rules

Do not execute this framework. Route to the current owner and stop after the replacement path is explicit.

## Evidence Standard

Historical references remain evidence of prior project design only. The deprecated framework is not company evidence and does not authorize new content decisions.

## Business-Model Adaptations

No new business-model adaptation is maintained here. Use the replacement frameworks.

## Output Contract

Return the applicable canonical replacement and the upstream artifact it requires.

## Failure Modes

Running deprecated logic, copying it into another project, mixing strategic direction with execution, or treating historical status as current authority.

## ContextOps Handoff

Campaign Role Architecture remains in Marketing ContextOps. Strategic Creative Direction and Content Execution are owned by the Content Operating System.

## Evaluation Notes

The original 0.1.0 framework was structurally reviewed but not validated in a real project run before its responsibilities were separated.

## Evolution Triggers

Retain this compatibility record while historical links exist. Remove it only through an explicit link-migration and provenance decision.
