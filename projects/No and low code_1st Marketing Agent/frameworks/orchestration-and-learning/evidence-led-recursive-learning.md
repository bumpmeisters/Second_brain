# Evidence-Led Recursive Learning

## Framework Job

Convert completed work and user feedback into reusable patterns and controlled improvements.

## Classification And Fidelity

Original project framework.

## Use When

- A meaningful run or artifact provides enough evidence to evaluate what worked.

## Do Not Use When

- No completed work exists or conclusions are only impressions.

## Minimum Required Inputs

- Artifacts, goal, evidence base, user feedback, observed friction, decisions, and outcomes where available.

## Core Model

Review evidence, separate case facts from reusable patterns, score quality/framework usefulness, propose minimal changes, and register learning.

## Question Engine

### Minimum Viable Questions

- What goal and artifacts are being reviewed?
- What demonstrably worked?
- What failed or slowed work?
- What caused the issue?
- Which lesson is case-specific?
- Which pattern transfers?
- What should change next time?
- What evidence would validate the change?

### Deepening Questions

- Was failure caused by framework, context, selection, or execution?
- What decision should be preserved?
- Which quality dimension was weakest?

### Counter-Questions

- Are we generalizing from one case?
- Did success depend on hidden context?
- Would the proposed update add complexity?

### Optional Modules

- Framework usefulness.
- Skill/workflow update.
- Pattern library.
- Quality score.

## Branching And Stop Rules

Apply clear factual fixes immediately. Queue structural changes until repeated evidence or severe failure supports them.

## Evidence Standard

Use completed artifacts, logs, feedback, measurements, and comparison outputs. Explain every score.

## Business-Model Adaptations

Patterns should record conditions and model-specific limits rather than claim universal transfer.

## Output Contract

What worked, failures, causes, reusable patterns, quality scores, updates, evidence, and next evaluation.

## Failure Modes

Vague lessons, company facts promoted as universal, broad rewrites, and self-modification without review.

## ContextOps Handoff

Feeds framework backlogs, skills, workflows, tools, decisions, and next tests.

## Evaluation Notes

Applied throughout project retrospectives and the Framework Builder evolution model.

## Evolution Triggers

Revise when learning logs become unused, repetitive, or fail to improve later runs.
