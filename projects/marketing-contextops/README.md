# Marketing ContextOps

**Summary**: An inactive control shell for the future shared Context Intelligence capability of the federated Agentic Marketing System.

## Current maturity

This directory was created in approved checkpoint P2A to make its future boundary reviewable before migration. It contains no active methods, skills, workflows, tools, sources, company assets, or routing authority.

Current files:

- `AGENTS.md` — inactive capability boundary and agent constraints.
- `decisions/log.md` — forward record of shell and later authority decisions.

The active capability remains in `projects/No and low code_1st Marketing Agent/`. Its files and the root `.agents/skills` discovery wrappers remain unchanged.

## Target role after activation

Marketing ContextOps is intended to produce governed context for later Brand, GTM, Campaign, and Content decisions:

```text
approved knowledge delta
  -> company and claim context
  -> market and buying context
  -> segmentation and audience understanding
  -> framework fit and proof-led positioning
  -> GTM context handoff
```

It will own reusable methods, stage contracts, and validation logic. The initiating source project will own the concrete outputs. It will not own protected sources, concrete Brand Core assets, ABM account plans, campaign assets, content assets, approvals, or performance evidence.

## Later activation requirements

- one approved owner and disposition for every migrated component;
- explicit decisions for shared-capability hotspots;
- atomic root-wrapper and operational-reference transition;
- positive and negative regression fixtures;
- proof that historical references and protected sources remain intact;
- a tested rollback path.

No additional folder or artifact is authorized merely because it appears in the target model.
