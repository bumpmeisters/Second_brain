# BUILD and Loop Orchestration Source Summary

**Summary**: Source-bundle summary of Austin Marchese material on loop orchestration and the BUILD pattern for a self-improving, file-based AI work environment.

---

## What these sources are

The bundle contains a seven-slide visual deck, a prompt-oriented transcript/synthesis, and a longer implementation guide. The material attributes the BUILD mnemonic and loop examples to Austin Marchese, but the files also contain AI-generated synthesis and product-specific interpretation. Treat attribution and current product mechanics as `needs verification` unless checked against the original creator material and official documentation (source: 20260629_LOOPS by Austin Marchese.pptx; source: 20260629_BUILD_Self-improving framework by Ausin Machese.docx; source: 20260630_BUILD Framework Guide for Claude Code.docx).

## BUILD pattern

- **Base**: establish project instructions, a raw/curated knowledge split, and a small number of reusable capabilities.
- **Upload**: bootstrap the system from selected high-signal historical material rather than indiscriminately importing everything.
- **Inflow**: create repeatable sync processes for sessions, connected systems, and curated external content.
- **Loop**: turn accepted corrections and operational failures into reviewable improvements, with low-risk changes separated from changes requiring approval.
- **Drive**: add orchestration and cadence only after the underlying ingestion and improvement capabilities are trustworthy (source: 20260629_BUILD_Self-improving framework by Ausin Machese.docx; source: 20260630_BUILD Framework Guide for Claude Code.docx).

## Loop-design patterns

- Start from a specific task, measurable goal, and explicit done rule.
- Use separate verification where possible; do not let the producer declare its own success without an independent check.
- Keep approval pauses during training, then remove only those pauses that repeated evidence shows are safe to automate.
- Write both the deliverable and a memory/run-history artifact describing what happened, what failed, and what should change next time.
- Break qualitative goals into smaller checkpoints because vague goals are difficult to verify and easier for an agent to drift from (source: 20260629_LOOPS by Austin Marchese.pptx).

## Caveats

- These are creator/practitioner patterns, not independently validated standards.
- Several prompts assume Claude-specific files, routines, hooks, and skill behavior that may be version-sensitive.
- Self-improvement should update durable knowledge only after review; unchecked output can compound errors as easily as lessons.
