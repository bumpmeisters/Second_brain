# Tina Claude Cowork System Source Summary

**Summary**: Source summary for Tina Huang's Lonely Octopus resource on setting up a Claude Cowork system with operating instructions, PRDs, data layers, skills, dashboards, and an autonomous builder pattern.

---

## What the source is

The source is a screenshot of a Lonely Octopus resource document titled "How to Set Up Your Claude Cowork System from Scratch (With Prompts You Can Steal)" by Tina Huang, dated May 2026 (source: tina-claude-cowork-system-2026-06-03.png).

The resource explains Tina's Claude Cowork setup, including operating instructions, PRD writing, daily digest and investment dashboard examples, and an autonomous builder pattern for building new software while she sleeps (source: tina-claude-cowork-system-2026-06-03.png).

## Key claims and ideas

- The source says the key to getting serious results from Claude Cowork is starting with a detailed PRD that acts like a blueprint for the system and projects to build (source: tina-claude-cowork-system-2026-06-03.png).
- Tina's operating instructions emphasize four behaviors: PRD first, pushback and clarification, aggressive note-taking, and reversibility for hard-to-undo actions (source: tina-claude-cowork-system-2026-06-03.png).
- The build logic uses a data-lake analogy: first create the data layer and pipelines, then build dashboards, skills, morning briefs, and builders on top of that layer (source: tina-claude-cowork-system-2026-06-03.png).
- Tina's example starter projects include an investment dashboard, daily digest, skills suite, and autonomous builder (source: tina-claude-cowork-system-2026-06-03.png).
- The workflow includes creating a local folder/project, handing the PRD to Cowork, following the build plan hour by hour, and finishing with notifications and end-to-end testing (source: tina-claude-cowork-system-2026-06-03.png).
- The autonomous builder pattern uses pending, in-progress, done, and failed folders, with a scheduled task checking for approved PRDs and moving builds through those states (source: tina-claude-cowork-system-2026-06-03.png).
- Tina says memory management matters more as the system scales, and she describes documentation as a habit to build in from the start (source: tina-claude-cowork-system-2026-06-03.png).

## Caveats

- This is a screenshot of a resource page, not the full video or the linked prompts; details that were behind "View" links are not available in this source (source: tina-claude-cowork-system-2026-06-03.png).
- The source describes Tina's setup, not Rolf's final system design. Any use in this vault should be treated as an adaptable pattern, not a literal implementation plan.
- Product-specific claims about Claude Cowork may change and should be checked against current product documentation before implementation.
