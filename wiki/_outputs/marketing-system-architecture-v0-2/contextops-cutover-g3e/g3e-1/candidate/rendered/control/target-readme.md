# Marketing ContextOps

**Summary**: Active shared Context Intelligence capability for the federated Agentic Marketing System. It owns reusable methods and contracts; initiating source projects own all concrete business artifacts.

## Current maturity

The controlled G3E cutover moves the reviewed ContextOps framework, skill, and workflow set from the historical project root to this system. Root discovery wrappers and current operational references switch atomically only after exact approval, green regression evidence, and a verified rollback snapshot.

Current system surface:

- `AGENTS.md` — active capability boundary and source-project routing rules.
- `frameworks/` — canonical Marketing ContextOps framework library.
- `skills/` — canonical bounded ContextOps skills.
- `workflows/` — stage, handoff, runbook, and development workflows.
- `decisions/log.md` — append-only authority and architecture record.

## Operating role

```text
approved knowledge delta
  -> company and claim context
  -> market and buying context
  -> segmentation and audience understanding
  -> framework fit and proof-led positioning
  -> GTM context handoff
```

Marketing ContextOps supplies the methods for these stages. It does not own the resulting company packet, Brand Core, positioning decision, GTM plan, campaign, content object, approval, performance record, or learning episode.

## Source-project contract

- Every concrete run names one exact existing repository-relative `source_project`.
- Root Second Brain owns default source custody and durable Root knowledge.
- Concrete outputs are written only to the initiating source project.
- Existing Legacy-embedded company projects remain at their current paths until a separate admission checkpoint.
- No local source library, company workspace, or generic `memory/` store is authorized here.

## Sibling boundaries

- `projects/ABM-operating-system/` remains the specialized account-based GTM capability.
- `projects/content-operating-system/` remains the shared content and expression capability.
- `projects/marketing-operating-system/` remains a draft interoperability umbrella with no operational authority.
- The residual historical root `projects/No and low code_1st Marketing Agent/` retains provenance and its embedded source projects but no shared ContextOps authority.

## Verification

Structural changes require exact component and wrapper manifests, source-project ownership tests, single-controller checks, Root Wiki Integrity Fast, MOS federation regressions, and a tested rollback path. Passing tests do not grant authority without explicit approval.
