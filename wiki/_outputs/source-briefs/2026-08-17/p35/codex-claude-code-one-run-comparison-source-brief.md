# Codex–Claude Code One-Run Comparison Source Brief

**Summary**: A practitioner gives two coding-agent systems the same broad prompt, tests the resulting applications, and compares product usability, architecture, tests, runtime, tokens, and cost. The durable lesson is about comparison design, not a winner.

## Durable signal

A nominally identical prompt does not control the harness, model mix, orchestration, budgets, environment, or interpretation of “production-ready.” More tests and tool calls did not prevent user-journey defects. A useful local comparison therefore needs explicit product acceptance criteria, real end-to-end task tests, aligned operating conditions, and separate outcome, trajectory, reliability, and efficiency measures.

## Caveats

This is one non-repeated experiment. The source itself reports inconsistent cost figures, many uncontrolled variables, and bugs in both outputs.

## Recommendation

`extended-claim` for [[agent-evaluation]]. Add the one-run comparison as a bounded failure example; exclude named-model superiority, cost, speed, token, and universal prompting claims.
