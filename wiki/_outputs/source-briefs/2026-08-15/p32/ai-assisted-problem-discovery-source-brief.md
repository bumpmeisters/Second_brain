# AI-Assisted Problem Discovery — Source Brief

**Summary**: A practitioner gave two agents the same open brief and observation surface, then compared the problems they chose. The useful pattern is not the claimed winner but the separation of problem discovery, human selection, and implementation.

## Useful evidence

- The brief asked each agent to inspect bounded work evidence, define a problem, propose a solution, and explain the choice (00:16–00:54; 02:39–03:08).
- Different agents selected a higher-leverage strategic bottleneck and a narrower, more finishable handoff problem (03:20–06:18).
- The author retained judgment over which consequence mattered and proposed comparing independent outputs before implementation (06:20–10:24).
- The later workflow mentions explicit access exclusions, problem-depth analysis, security, authentication, and business value (07:41–09:31).

## Caveats

- This is one practitioner’s anecdotal, non-controlled comparison.
- Named-model superiority, user-growth, token-consumption, privacy, and cost claims were not verified and should not be promoted.
- Broad access to local files and messages creates privacy, permission, and prompt-injection risk; evidence collection must be explicitly scoped.
- The archived track is an automatic German caption and distorts several product names.

## Proposed knowledge delta

Extend `wiki/applied-ai-use-cases.md` and create a reusable `wiki/ai-assisted-problem-discovery-preflight.md` only after approval. The artifact would define a bounded observation contract, independent candidate generation, evidence-and-risk comparison, human selection, and a separate implementation authorization gate.
