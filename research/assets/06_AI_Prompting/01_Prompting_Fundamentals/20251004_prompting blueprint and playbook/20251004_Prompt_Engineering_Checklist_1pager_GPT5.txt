# Prompt Engineering — 1?Page Checklist (2025)

**Goal:** A fast, reliable way to craft prompts and run end?to?end prompting with quality, safety, and reuse.

---

## 0) Foundational Trinity (the small spec)
- **Goal:** What to produce for whom (audience).  
- **Scope:** What’s in/out; avoid speculation.  
- **Success criteria:** How you’ll judge the answer.

**Output contract**
- Exact structure (table/JSON/bullets).  
- Example or schema.  
- “Return ONLY this format.”

---

## 1) Information Gravity
- Attach decisive artifacts (deck, transcript, research).  
- Add a 5?bullet digest (not whole PDFs).  
- If facts can change: add “verify before final.”

---

## 2) Draft smart (pick 1–2 controls if needed)
- **Step?Back:** principles ? micro?plan ? answer.  
- **Skeleton?of?Thought:** outline ? fill sections.  
- **Self?Consistency (k=3–7):** for tricky logic/math.

---

## 3) Verify & ground
- **Self?RAG:** decide to retrieve or skip.  
- **CRAG:** if weak retrieval, re?query and filter.  
- **CoVe/CRITIC:** write verification Qs ? check tools/web ? revise.  
- Require **citations** for unstable facts (news/laws/prices/specs).

---

## 4) Refine & compress
- Style pass for audience; keep schema strict.  
- Summarize assumptions & unresolved risks.

---

## 5) Cross?model critique (quick quality boost)
- Model A drafts ? Model B critiques ? Model A revises (+ short changelog).

---

## 6) Productionize (optional)
- Treat prompts as code (modules, tests, metrics).  
- Bake guardrails into templates (safety, scope).  
- Track KPIs (accuracy, hallucination rate, FCR/CSAT).

---

## Paste?ready micro?blocks

**Job spec**
```

Success criteria: {…}
```

**Context**


**Output contract**
```
<output_format>

```

**Reasoning switches**


**Verification**

**Guardrails**
```

```
