# Workflow lens

Trace trigger → input → decision → state/artifact → handoff → result → verification. Name who owns each decision and what evidence permits continuation. Inspect concrete templates, schemas and scripts where they exist.

Distinguish a prescribed sequence from machinery that enforces it. Find the response to incomplete input, review rejection, interrupted work and obsolete intermediate state. Do not infer persistence, independence or retries from a prompt alone.

Output a small sequence or table and explain the mechanism that makes the workflow useful. Translate into our work only after the source behavior is clear. A software example may teach a transferable handoff method without justifying adoption of its whole software process.
