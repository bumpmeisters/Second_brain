# Quality and learning lens

Separate five levels: author claim, explicit contract, implementation, verification mechanism, measured outcome. A test file shows a proposed check, not a passing run. A checked-in result is versioned project evidence, not independent reproduction.

Follow one feedback path: observed failure → recorded evidence → review → changed artifact → renewed check. Determine which steps exist, which are instructions and which are absent. Examine whether reviewers see independent evidence, whether tests verify meaningful behavior and whether reported outcomes have a defined corpus and version.

Preserve negative findings and missing checks. Assess evaluation quality separately from the attractiveness of the idea. Runtime evaluation requires a concrete separately authorized experiment, not merely the existence of an executable test.
