# AI Work Blueprint Reference

## Workshop Metaphor

| Layer | Image | Job |
|---|---|---|
| Specification | Blueprint on the wall | Make goal, context, boundaries, and output clear. |
| Verification | Quality station at the exit | Check whether the result is fit for purpose. |
| Environment | The workshop itself | Keep reusable tools, rules, knowledge, examples, and routines. |

## Use Cases

- Research, source synthesis, and deep research
- Reports, decks, briefings, and decision documents
- Marketing strategy, campaigns, personas, and content
- PRDs, project planning, process design, and product work
- Coding, automation, data analysis, and tool building
- Learning, second-brain maintenance, and repeatable personal workflows

## Verification Is Broader Than Fact Checking

Depending on the task, verify:

- factual accuracy
- source support
- usefulness for the decision
- fit to audience and context
- structure and clarity
- brand, tone, or style
- implementation risk
- missing assumptions
- contradiction with prior material
- need for human approval

## Environment Subsystems

| Subsystem | Purpose |
|---|---|
| Operating instructions | Persistent rules and maps such as AGENTS.md or CLAUDE.md. |
| Knowledge base | Raw sources compiled into durable linked knowledge. |
| Procedural skills | Repeatable workflows in SKILL.md files, templates, or scripts. |
| Deterministic guardrails | File permissions, hooks, checks, or approval gates that can block unsafe action. |

## Spec Maturity

- `spec-first`: create a clear spec before execution.
- `spec-anchored`: keep the spec updated as the project evolves.
- `spec-as-source`: use the spec as the main control surface for repeated or technical work.

Use the lightest maturity level that makes the work reliable.

## Golden Rule

Execution can be delegated to AI. Understanding cannot. The user remains responsible for goal, context, judgment, boundaries, and approval.
